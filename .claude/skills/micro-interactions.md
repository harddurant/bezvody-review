# Микро-отклики: пять обязательных состояний интерактивного элемента

Любая кнопка, строка-переход, чекбокс, поле ввода и чип в `index.html` обязаны
иметь все пять состояний. Отсутствие одного — находка обхода (`audit.js`:
«немая кнопка»). Значения — под токены проекта (`--ez`, `--tap`, `--gym-in`,
`--ac`), кривые — из `apple-springs.md`, контраст и размеры — из
`ios-accessibility.md`.

## 1. Default — покой
- Форма и цвет читаются как «нажимаемое» без наведения: фон-подложка
  (`rgba(255,255,255,.06)` на карточке, `#2C2C2E` тихая кнопка, лайм — одно
  главное действие на экране) или шеврон справа у строки-перехода.
- Текст ≥ 4.5 : 1, зона касания ≥ 44 pt, зазор до соседа ≥ 8 pt.
- Без тени и рамки как единственного признака; без курсора-подсказок (телефон).

## 2. Active — физическое сжатие
- `:active{ transform: scale(k) }` мгновенно (transition 0 на входе), возврат
  пружиной 1.1 из `apple-springs.md` (или `transition: transform .18s var(--ez)`).
- Коэффициент по размеру: крупная кнопка (CTA, 54 px) — **0.96**; строка списка
  и тихая кнопка — **0.98**; кружок/иконка (≤ 44 px) — **0.86–0.90**.
- Плюс лёгкое потемнение/подсветка фона (`background: rgba(255,255,255,.05)` у
  строк; `filter: brightness(.96)` у лайма) — чтобы отклик читался и там, где
  масштаб незаметен.
- `-webkit-tap-highlight-color: transparent` — системную синюю заливку не показывать.
- Отклик — на `touchstart`, не на `click`: палец должен видеть ответ до отпускания.

## 3. Loading — блокировка + аккуратный индикатор
- Элемент блокируется от повторного тапа (`disabled` или `aria-busy="true"` +
  `pointer-events:none`), но **не меняет размер** — текст остаётся, рядом
  индикатор 16 px (кольцо `border: 2px solid currentColor; border-right-color:
  transparent; animation: spin .8s linear infinite`).
- Показывать индикатор только если ожидание > 300 мс (иначе мигание); после
  300 мс — обязательно, «молчащая кнопка» читается как сломанная.
- Дольше 3 с — текст состояния («Считаю…», «Синхронизирую…»), дольше 10 с —
  возможность отменить.
- Никаких полноэкранных спиннеров для действия одного элемента.

## 4. Done — фиксация успеха
- Момент фиксации — один: смена значка/текста (галочка, «Записано», число
  «3 из 5»), пружина 1.3 (bounce) на элементе-источнике, тост — только если
  результат не виден на месте.
- Цвет успеха — акцент проекта (лайм) или системный `#30D158`; не красный/жёлтый.
- Состояние держится, пока данные его подтверждают (галочка на записанном
  подходе живёт до удаления), не «гаснет через 2 с» — гаснуть может только тост.
- Тактильный отклик там, где он есть (`navigator.vibrate` после жеста), и
  никогда — на автоматических событиях.
- Ошибка — та же схема с другим знаком: элемент остаётся, текст называет причину
  и следующий шаг; окна `alert()` не используются.

## 5. Disabled — читаемая «слепота» без падения контраста ниже нормы
- Элемент видно и читается: текст **≥ 3 : 1** к фону (на `#000`/`#1C1C1E` это
  `rgba(255,255,255,.4)`, не `.2`), фон приглушён (`opacity:.55` у контейнера
  или `background: rgba(255,255,255,.04)`), без `:active`-сжатия и без шеврона
  «переход».
- Причина рядом одной строкой («Нужен вес — запиши на «Еде»») или по тапу по
  самому элементу (`aria-disabled` вместо `disabled`, чтобы тап дошёл).
- Никогда не прятать контрол вместо блокировки — человек не найдёт, «куда
  делось» (HIG tab-bars: «never disable or hide … explain why»).
- `cursor:not-allowed` не нужен (телефон); `pointer-events:none` только если
  объяснение уже на экране.

## 6. Чек-лист при сборке элемента
1. Пять состояний описаны в CSS рядом (один блок на класс, не по месту).
2. Масштаб только `transform`, цвета — переменными темы, кегли — шкалой.
3. Active < 100 мс до отклика; Loading показан после 300 мс; Done — пружина 1.3.
4. Disabled контрастен ≥ 3 : 1 и объяснён.
5. Мутация правила гейта (снять `:active`, снять `min-height:44px`) — красная.
